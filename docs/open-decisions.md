| DA-0004 | The ownership core does not know which state transitions require a human act: the v2 schema declares `states` per path and does not declare which transitions between them block without human promotion. | DA-0005 | How a domain plugin finds, through the core's library, the `owned[]` paths that carry its block. | DA-0006 | What a plugin block with no configuration means in the v2 schema. A plugin may want to claim a path without having any key to declare in it, and today `sdd:` with no value arrives as `null` and `sdd: {}` arrives as an empty map — the core keeps both as a present block, and no rule says whether that is a valid declaration of participation or an error by whoever forgot to fill it in. Options: both are valid and the core normalizes to an empty map; only the empty map is valid and the null value is an error; or neither is valid and a plugin that has nothing to configure needs an explicit participation key                                                                                                                                                                                                                                                                   | resolved | ADR-0020    | —                                                 | 2026-09-23 |
| DA-0007 | Who notices a plugin listed in `plugins:` that is not installed. The list catches a mistyped block name, but a right name of an absent plugin makes the core ignore its blocks and nobody else reads them — the rules of that domain stop being charged silently, which is the failure the list exists to close. The core, running as a library or as a plugin, has no way today to know which other plugins are present. Options: each plugin announces its own presence to a core check, which flags a listed name with no announcement; accepting the silence and documenting that `plugins:` only protects against typos; or leaving the charge to each plugin's installation check                                                                                                                                                                                                            | open     | —           | —                                                 | 2026-09-23 |
| DA-0008 | What the repository root presents now that the repository is `esliph/agent-plugins`, a marketplace meant to host plugins that are not about documentation. The root `README.md` and `CLAUDE.md` still present the whole repository as `@esliph/living-docs`, and neither `packages/living-docs/` nor `packages/ownership/` has a README of its own. `ADR-0027` names the root `esliph` and does not say what its presentation and agent contract cover. Options: the root becomes the marketplace's page (the list of plugins and how to install them) and the toolkit's presentation moves to `packages/living-docs/`, with a README per package; the root keeps presenting living-docs until a second domain plugin exists; or the root README becomes the marketplace's page while `CLAUDE.md` stays as the living-docs agent contract, since this repository keeps using the toolkit on itself | resolved | ADR-0035    | `README.md`, `CLAUDE.md`                          | 2026-09-29 |
