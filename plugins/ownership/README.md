# ownership

One file, `.ownership.yml`, says who owns each path of a repository, which files
are generated by a command, and which document has to change when a piece of
code changes. This plugin checks those promises — in the Claude Code session,
at commit time and in CI.

It works on its own, and it is the core that
[`living-docs`](../living-docs/README.md) builds on.

## Install

```text
/plugin marketplace add esliph/agent-plugins
/plugin install ownership@esliph
```

Requires Node 24 or later on the machine. The hooks read `.ownership.yml` (or
`docs/.ownership.yml`) from the project root; in a project without one, they do
nothing.

## The ownership file

```yaml
version: 2

owned:
  - path: docs/requirements/rules.md
    owner: '@team-payments'
    states: [draft, active, revoked]

generated:
  - path: docs/api.gen.md
    command: node tools/gen-api.ts # prints the expected content

watches:
  - code: 'src/domain/**'
    doc: docs/requirements/rules.md
    reason: 'a new behavior needs a rule before the code'
  - code: 'src/api/**'
    doc: CHANGELOG.md
    consumer-visible: true
    reason: 'the API is what consumers depend on'

ignore:
  - 'node_modules/**'
```

| Key         | Declares                                                                                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `owned`     | The owner of each path, the states an item under it may be in, and optionally the skill that maintains it. Every owned path must also appear in `CODEOWNERS`.    |
| `generated` | Files produced by a command. They change by running the command, never by hand, and the committed copy must match what the command prints.                       |
| `watches`   | Code linked to the document that describes it. With `consumer-visible: true`, the document is the changelog and a change needs an entry under `## [Unreleased]`. |
| `ignore`    | Paths outside the coverage check. Every other file must fall under an `owned` entry.                                                                             |
| `include`   | Other ownership files, for a subdirectory that declares its own paths.                                                                                           |

A plugin built on the core (such as `living-docs`) lists itself in `plugins:`
and adds its own block under its name.

## In the session

| When                                               | The hook                                                |
| -------------------------------------------------- | ------------------------------------------------------- |
| You edit a generated file by hand                  | Denies the edit and names the command that produces it. |
| You edit watched code                              | Reminds you of the document that describes it.          |
| You edit a source that other documents derive from | Reminds you of those documents.                         |
| You commit watched code without its document       | Asks before the commit goes through.                    |

Only the first one blocks. If Node, a dependency or the file is missing, every
hook stays silent.

## In CI

```bash
ownership validate                 # the whole tree
ownership validate --base origin/main  # plus the checks that read the branch diff
ownership explain <path>           # the rule that applies to a path, and where each part came from
```

`validate` exits with 1 when a check fails:

| Check                              | Fails when                                                                               |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| `ownership/owner-coverage`         | A file has no owner, an owned path does not exist, or `CODEOWNERS` misses an owned path. |
| `ownership/declared-state`         | An item is in a state its path does not declare.                                         |
| `ownership/generated-drift`        | A generated file differs from what its command prints.                                   |
| `ownership/derivation-resolves`    | A document derived from a source does not point to it, or points to a file that is gone. |
| `ownership/watch-satisfied`        | With `--base`: watched code changed and its document did not.                            |
| `ownership/consumer-change-logged` | With `--base`: a consumer-visible change has no entry under `## [Unreleased]`.           |

The two diff checks accept a written waiver in a commit message of the branch:
`Docs: none — <reason>` for a watched document, `Changelog: none — <reason>` for
the changelog.

The commands run on the current directory; set `OWNERSHIP_REPO_ROOT` to check
another one. The package is not on npm yet: until it is, run the CLI from a
checkout of this repository with `node plugins/ownership/plugin/src/cli/index.ts`.
